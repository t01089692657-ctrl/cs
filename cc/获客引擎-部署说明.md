# 获客引擎 部署说明

「一键全渠道获客」在**预览版**里是本地模拟数据；部署到服务器、接入下面几个 API 后，
它会变成**真实的后端 AI agent**：自己去各平台找公司、扒官网、补邮箱、打分、写开发信。

前端**一行都不用改** —— 所有对外调用都收在 `cc/js/services.js` 一个文件里，
部署时只需实现服务器端接口，把该文件里的三个函数从「模拟」改成「调后端」。

---

## 一、整体架构

```
浏览器（现有前端，不改）
   │  调用 App.services.discoverProspects() / sendOutreach()
   ▼
你的服务器：获客 agent 服务（新增，见下）
   ├─ 大模型 API（OpenAI / Claude / DeepSeek / 通义千问…）— 判断意向、写开发信
   ├─ 找公司：Google 搜索 API（SerpAPI / Google Custom Search）
   │           + 海关数据 API（ImportYeti / Volza）
   │           + B2B 目录
   ├─ 扒官网：Crawl4AI（自建，跑大批量）+ Firecrawl（兜底反爬/难抓页面）
   ├─ 找邮箱：Hunter.io / Apollo.io API
   └─ 发信：你登录的邮箱 SMTP
```

数据来源两种模式（前端可随时切换，已做好）：
- **合规模式（默认）**：只用 Google 搜索、海关数据、B2B 目录、行业展会 + 找邮箱 API。稳定合法。
- **全网模式**：额外抓 LinkedIn / X / YouTube / Facebook。覆盖更广，但违反这些平台的服务条款，有账号被封与法律风险（参考 hiQ v. LinkedIn 案），谨慎使用。

## 二、需要准备的账号 / API Key

| 用途 | 服务 | 备注 |
|---|---|---|
| 大模型 | OpenAI / Claude / DeepSeek / 通义千问 之一 | 打分 + 写开发信 |
| 抓取（自建） | [Crawl4AI](https://github.com/unclecode/crawl4ai) | 开源免费，部署在你服务器上跑批量 |
| 抓取（兜底） | [Firecrawl](https://github.com/firecrawl/firecrawl) | 反爬难页面，托管 API 按量付费 |
| 找公司-搜索 | SerpAPI 或 Google Custom Search | 拿搜索结果里的公司官网 |
| 找公司-海关 | ImportYeti（美国免费）/ Volza | 真实进口商名单 |
| 找邮箱 | [Hunter.io](https://hunter.io) / [Apollo.io](https://apollo.io) | 按公司域名/人名反查邮箱 |
| 发信 | 你的企业邮箱 SMTP | 前端「登录发信邮箱」已做好 |

配置入口已做好：前端「主动客户开发 → 获客渠道 → ⚙ 获客引擎」里填这些 key。

## 三、后端要实现的 3 个接口

对应 `cc/js/services.js` 里的三个函数，服务器端实现后，把该文件改成 `fetch` 调用即可。

### 1. `POST /api/discover` —— 全渠道获客
入参：`{ keyword, countries, mode }`
处理（获客 agent 流程）：
1. 按 `keyword + countries` 调搜索/海关/B2B API，得到候选公司官网列表（`mode=full` 时加社媒源）
2. 对每个官网用 Crawl4AI 抓取（失败/反爬的用 Firecrawl 兜底），拿到页面内容
3. 用 LLM 从页面提取：公司名、国家、联系人、职位、信号
4. 用 Hunter/Apollo 按域名补全负责人邮箱
5. 用 LLM 结合 ICP 打分（0-100）
返回：`[{ channel, company, website, country, person, role, email, signals[], score }]`
（与现在模拟返回的结构完全一致，前端表格直接用）

### 2. `POST /api/outreach/send` —— 批量发开发信
入参：`{ accountId, prospects[], template }`
处理：用已登录邮箱 SMTP 逐封发送，`{name}/{company}/{country}` 用每家真实信息替换；控制发送频率、加退订链接、记录送达。
返回：`{ sent, failed, details }`

### 3. `POST /api/email-account` —— 保存发信邮箱
把邮箱账号/授权码存服务器端（**不要下发给前端**），发送时服务器用它连 SMTP。

## 四、部署后如何切到真实模式

编辑 `cc/js/services.js`，把这三处的模拟实现换成 `fetch('/api/...')`：

```js
// 现在（演示）：
S.discoverProspects = function (opts) { /* 本地生成模拟数据 */ };
// 部署后：
S.discoverProspects = function (opts) {
  return fetch('/api/discover', {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(opts)
  }).then(function (r) { return r.json(); });
};
```

`sendOutreach`、`emailAccount.save` 同理。改完前端所有页面、按钮、流程都不变，
用户操作方式跟预览版一模一样，只是数据变真实。
